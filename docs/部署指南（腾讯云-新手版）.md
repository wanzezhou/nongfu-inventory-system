# 部署指南（腾讯云 · 新手版）

> 适用：农夫山泉经销商进销存系统（Vue3 + Element Plus 前端 / Node.js + Express 后端 / MySQL 8）
> 目标读者：第一次做服务器部署的开发者。**全程照抄命令即可**，所有需要你替换的值都用 `<尖括号>` 标出。
> 相关文档：`docs/交接文档.md`（架构与背景）、`docs/项目概览.md`（唯一事实源）。

---

## 〇、先看懂部署后的样子（30 秒建立全局认知）

你的系统本机跑起来是**两个进程**：后端 Node 监听 3000，前端 vite 开发服务器监听 5173，浏览器访问 5173，vite 再把 `/api` 转发给 3000。

**生产环境不能这么跑**（vite 开发服务器性能差、不能长期对外服务）。生产环境改成一个 **nginx** 顶在最前面：

```
                 ┌──────────────────────────────────────────────┐
   用户浏览器 ────▶│  nginx（80 / 443）                           │
                 │                                              │
                 │  ①  /            → 直接返回前端静态文件        │
                 │                     /opt/nongfu/frontend/dist │
                 │  ②  /api/        → 转发给后端 3000            │
                 │  ③  /product_images/ → 转发给后端 3000（商品图）│
                 │  ④  /uploads/    → 转发给后端 3000（上传文件）  │
                 └───────────────────────┬──────────────────────┘
                                         │
                              ┌──────────▼──────────┐
                              │ Node 后端 :3000      │  ← pm2 守护，开机自启
                              │ backend/src/app.js  │
                              └──────────┬──────────┘
                                         │
                              ┌──────────▼──────────┐
                              │ MySQL 8 :3306        │  ← 只允许本机访问
                              │ nongfu_inventory     │
                              └─────────────────────┘
```

**三句话记住**：

1. 前端是**静态文件**（构建产物），交给 nginx 直接发，不需要 Node。
2. 后端是**常驻服务**（Node 进程），由 pm2 守护，只监听本机 3000，**不对公网开放**。
3. MySQL **只监听本机**，绝不对公网开放 3306。

## 一、要部署哪些文件和目录

### 1.1 三类东西的分工

| 类别             | 是什么                            | 具体位置                                                              | 谁来运行/提供  |
| ---------------- | --------------------------------- | --------------------------------------------------------------------- | -------------- |
| **前端静态资源** | 浏览器下载的 HTML/CSS/JS          | `frontend/dist/`（**服务器上构建产出**）                              | nginx 直接读取 |
| **后端服务**     | 常驻 Node 进程（业务逻辑 + 接口） | `backend/src/`                                                        | pm2 守护       |
| **依赖**         | 第三方库                          | `backend/node_modules/`、`frontend/node_modules/`（**服务器上重装**） | Node           |
| **配置**         | 数据库地址、密钥、端口            | `backend/.env`、`frontend/.env.production`、nginx conf、pm2 配置      | 各自程序读取   |
| **数据**         | 数据库结构与数据                  | `database/full_schema_data.sql`                                       | 导入 MySQL     |
| **运行期资源**   | 商品图片                          | `商品档案/商品图片/`（⚠️ **在仓库根目录，不在 backend 内**）          | 后端静态中间件 |

### 1.2 上传清单（逐条核对）

| 路径                                                              |           传不传            | 说明                                                                                                                                   |
| ----------------------------------------------------------------- | :-------------------------: | -------------------------------------------------------------------------------------------------------------------------------------- |
| `backend/src/`                                                    |         ✅ **必传**         | 后端全部源码                                                                                                                           |
| `backend/package.json`、`backend/package-lock.json`               |         ✅ **必传**         | 服务器据此装依赖（`npm ci` 需要 lock 文件）                                                                                            |
| `backend/.env`                                                    | ✅ **传，但必须改成生产值** | ⚠️ **不要直接把本机那份拷上去**（见 1.4）                                                                                              |
| `backend/scripts/`                                                |            ✅ 传            | `init_db.js`（建库）、`export_dump.js`（备份导出）必需；`smoke_*.js` 冒烟脚本可传可不传                                                |
| `frontend/src/`、`frontend/index.html`、`frontend/vite.config.js` |         ✅ **必传**         | 服务器上要执行 `npm run build`                                                                                                         |
| `frontend/package.json`、`frontend/package-lock.json`             |         ✅ **必传**         | 同上                                                                                                                                   |
| `frontend/.env.production`                                        |            ✅ 传            | 生产配置，内容 `VITE_API_BASE=/api`（**保持默认即可**，见 1.3）                                                                        |
| `database/`                                                       |         ✅ **必传**         | `full_schema_data.sql` 建库；`migration_*.sql` 后续增量                                                                                |
| `商品档案/商品图片/`                                              |      ✅ ✅ **必传！**       | ⚠️ **134 张商品图，23MB**。后端代码里路径是 `backend/src/../../商品档案/商品图片`，也就是**仓库根目录下**。**漏传 = 全站商品图片裂图** |
| `.git/`                                                           |          ✅ 建议传          | 用 `git clone` 方式部署就自带；**这是后面能一键回滚的基础**                                                                            |
| `frontend/dist/`                                                  |         ❌ **不传**         | 服务器上重新构建（本机构建产物可能带本机路径）                                                                                         |
| `node_modules/`（任何一层）                                       |         ❌ **不传**         | 体积巨大且平台相关，服务器上重装                                                                                                       |
| `backend/uploads/`                                                |           ❌ 不传           | 运行期产物（配送照片/报销凭证），空目录即可                                                                                            |
| `*.log`、`*.pid`、`frontend/vite.config.js.timestamp-*`           |           ❌ 不传           | 本机运行痕迹                                                                                                                           |
| 根目录 `package.json`、`eslint.config.mjs`、`scripts/`            |           ❌ 不传           | 这是本机**开发工具链**（ESLint/Prettier/husky/红线门禁），**生产环境不需要**                                                           |

> **一句话口诀**：源码要传、配置要改、依赖要重装、构建产物不要传、商品图片千万别忘。

### 1.3 前端为什么不用改配置？

`frontend/.env.production` 里是 `VITE_API_BASE=/api` —— 这是一个**相对路径**。
浏览器请求 `/api/orders` 时，nginx 会把 `/api/` 开头的请求转发给后端。前后端**同域**，因此：

- ✅ 不需要填 IP 或域名
- ✅ 不需要改 CORS
- ✅ 换域名不用重新构建

⚠️ **前提是 nginx 必须反代 `/api/`**。只反代一部分会让接口或图片 404（见 1.5）。

### 1.4 后端 `.env` 生产环境必改项

把 `backend/.env.example` 拷成 `.env` 再填，**不要**用本机那份。

```ini
# 服务端口（保持 3000，nginx 会转发到这里）
PORT=3000

# ===== 数据库：用「应用专用账号」，不要用 root =====
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=nongfu
DB_PASSWORD=<第2.3步设置的强密码>
DB_NAME=nongfu_inventory

# ===== 两个 JWT 密钥：必须各自独立随机，绝不相同 =====
# 生成：node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"  执行两次
JWT_SECRET=<32字节随机hex-第1次>
JWT_SECRET_MINI=<32字节随机hex-第2次>
MINI_TOKEN_TTL=2h

# ===== CORS：填真实访问地址，多个用英文逗号分隔 =====
# 同域部署（走 nginx）时浏览器不会发跨域请求，但仍建议填上真实域名
CORS_ORIGIN=https://<你的域名>,http://<你的域名>

# ===== ⚠️⚠️ 生产环境必须关掉本地开发登录 =====
MINI_DEV_LOGIN=0

# ===== 小程序凭据（若暂时不用小程序，留空即可）=====
WX_APPID=
WX_SECRET=
```

⚠️ **`JWT_SECRET_MINI` 缺失时后端会直接拒绝启动**（代码里刻意不留默认值）。

### 1.5 ⚠️ 最容易踩的坑：nginx 必须反代三条前缀

前端代码里商品图片用的是**站内相对路径**（例如 `/product_images/SPBM001_image.png`），
而且 `/uploads/`（配送照片、报销凭证）**带 Referer/Origin 白名单守卫**。

因此 nginx 必须把**三条**前缀都转发给后端 3000：

| 前缀               | 用途                | 漏配后果                   |
| ------------------ | ------------------- | -------------------------- |
| `/api/`            | 全部业务接口        | 页面打不开数据，接口全 404 |
| `/product_images/` | 商品图片            | **全站商品图片裂图**       |
| `/uploads/`        | 上传的配送照片/凭证 | 相关图片 403 / 404         |

完整 nginx 配置见 **第 2.7 步**（可直接复制 `deploy/nginx-nongfu.conf`）。

## 二、从零开始的部署步骤（Ubuntu 22.04 / 腾讯云 CVM）

> 用 CentOS 的话把 `apt` 换成 `yum`，其余一致。**以下命令逐条执行，每条执行完确认没有红色报错再往下。**

### 步骤 0：买服务器 + 开安全组（5 分钟）

**推荐配置**：2 核 4G、Ubuntu 22.04 LTS、系统盘 40G+（这个系统数据量小，2 核 4G 足够）。

到 **腾讯云控制台 → 云服务器 → 安全组**，只放行这三个端口：

| 端口 | 用途     | 来源                                      |
| ---- | -------- | ----------------------------------------- |
| 22   | SSH 登录 | **建议填你的本地公网 IP**，不要 0.0.0.0/0 |
| 80   | HTTP     | 0.0.0.0/0                                 |
| 443  | HTTPS    | 0.0.0.0/0                                 |

⚠️ **绝对不要放行 3306（MySQL）和 3000（后端）** —— 它们只在服务器本机内部使用。

> **域名**：想用域名访问，需要（a）在域名服务商把 A 记录解析到服务器公网 IP；（b）**国内服务器必须完成 ICP 备案**，否则 80/443 会被拦。
> **没域名也能先用**：直接 `http://<公网IP>/` 访问，先把系统跑通再上域名。

### 步骤 1：连上服务器 + 基础环境

```bash
# 1.1 登录（本机终端执行；Windows 可用 PowerShell / 宝塔终端 / Xshell）
ssh root@<你的服务器公网IP>

# 1.2 ⚠️ 设置时区为上海（必做！否则所有「按日期统计」的口径会错一天）
timedatectl set-timezone Asia/Shanghai
date    # 确认输出是 CST 北京时间

# 1.3 更新系统软件源
apt update && apt upgrade -y

# 1.4 安装基础工具
apt install -y curl git vim nginx
```

#### 1.5 安装 Node.js 20（后端运行环境，项目要求 `node >= 20`）

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
node -v      # 应输出 v20.x 或更高
npm -v

# 国内服务器建议换成国内镜像，装依赖会快很多
npm config set registry https://registry.npmmirror.com

# 安装 pm2（进程守护，让后端崩溃后自动重启、开机自启）
npm install -g pm2
pm2 -v
```

#### 1.6 安装 MySQL 8

```bash
apt install -y mysql-server
systemctl enable --now mysql      # 设为开机自启并立即启动
systemctl status mysql            # 看到 active (running) 即可，按 q 退出
```

### 步骤 2：建库、建账号、导入数据

#### 2.1 上传代码到服务器

三种方式，**新手推荐方式 A**：

| 方式                     | 命令/操作                                                                   | 优点                                             |
| ------------------------ | --------------------------------------------------------------------------- | ------------------------------------------------ |
| **A. git clone（推荐）** | `git clone https://github.com/<你>/nongfu-inventory-system.git /opt/nongfu` | 一次搞定；**后面能一键回滚**                     |
| B. 图形化 SFTP           | 用 WinSCP / FileZilla 把项目目录拖上去                                      | 直观，但每次更新要重拖                           |
| C. 宝塔面板              | 面板 → 文件 → 上传                                                          | 最省事，但**要额外配置 Node 项目管理器**，反而绕 |

```bash
# 方式 A：克隆到 /opt/nongfu（仓库里已包含商品图片，一并拉下来）
mkdir -p /opt && cd /opt
git clone https://github.com/<你的账号>/nongfu-inventory-system.git nongfu
cd /opt/nongfu && ls
```

> 私有仓库需配置 SSH 部署密钥：`ssh-keygen -t ed25519` → 把 `~/.ssh/id_ed25519.pub` 加到 GitHub 仓库的 Deploy keys → 用 `git@github.com:...` 地址克隆。

#### 2.2 创建数据库

```bash
# 登录 MySQL（Ubuntu 的 MySQL 8 默认 root 走 socket 认证，用 sudo 免密进入）
sudo mysql
```

进入 MySQL 交互界面后，**逐条执行**（把 `<强密码>` 换成你自己设的密码）：

```sql
-- ① 建库（字符集必须是 utf8mb4，否则中文和 emoji 会乱码）
CREATE DATABASE IF NOT EXISTS nongfu_inventory
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;

-- ② 建应用专用账号（只允许从本机连；不要用 root 跑应用）
CREATE USER IF NOT EXISTS 'nongfu'@'localhost' IDENTIFIED BY '<强密码>';

-- ③ 授权（只给它这一个库的权限）
GRANT ALL PRIVILEGES ON nongfu_inventory.* TO 'nongfu'@'localhost';

FLUSH PRIVILEGES;
EXIT;
```

#### 2.3 导入表结构与数据

```bash
# ⚠️ 用 root 导入（脚本里自带 CREATE DATABASE / DROP TABLE 语句，需要高权限）
sudo mysql --default-character-set=utf8mb4 < /opt/nongfu/database/full_schema_data.sql

# 校验：应输出 39（本系统共 39 张表）
mysql -u nongfu -p'<强密码>' -e \
  "SELECT COUNT(*) AS 表数量 FROM information_schema.tables WHERE table_schema='nongfu_inventory';"

# 校验关键表有数据
mysql -u nongfu -p'<强密码>' nongfu_inventory -e \
  "SELECT COUNT(*) AS 商品数 FROM products; SELECT COUNT(*) AS 订单数 FROM orders;"
```

> ⚠️⚠️ **重要警告**：`full_schema_data.sql` 里含 `DROP TABLE` 语句。
> **这是首次部署可以放心执行**（库里本来就空的）；但**以后每次执行都会清空现有数据**。
> 上线后要重新导入，**必须先用 `mysqldump` 备份**（见 4.1）。

> 💡 后续如果数据库结构有更新（`database/migration_*.sql`），用：
>
> ```bash
> mysql -u nongfu -p'<强密码>' nongfu_inventory < /opt/nongfu/database/migration_xxx.sql
> ```

### 步骤 3：部署后端

```bash
cd /opt/nongfu/backend

# 3.1 创建生产配置文件（照着 deploy/backend.env.production.example 填）
vim .env
#  按 i 进入编辑 → 粘贴/修改内容（见本文 1.4 节）→ 按 Esc → 输入 :wq 回车保存
#  ⚠️ 校验项：DB_USER=nongfu、DB_PASSWORD 与 2.2 一致、两个 JWT 密钥互不相同、MINI_DEV_LOGIN=0

# 3.2 安装依赖（只装生产依赖，不装 nodemon 等开发工具）
npm ci --omit=dev

# 3.3 先手工启动一次，确认能连上数据库
node src/app.js
```

**看到这两行就是成功**：

```
数据库连接成功
服务器运行在 http://localhost:3000
```

再开一个 SSH 窗口（或按 `Ctrl+C` 停掉后继续）验证：

```bash
curl http://127.0.0.1:3000/health
# 期望：{"code":200,"message":"ok","data":{"status":"healthy", ...}}
#  ⚠️ 返回 503 + "数据库不可用" → 是 .env 数据库配置问题，去查 3.4
```

`Ctrl+C` 停掉手工进程，改用 pm2 守护：

```bash
# 4.1 用 pm2 启动（⚠️ 必须在 backend 目录下，因为 .env 是按「当前工作目录」加载的）
cd /opt/nongfu/backend
pm2 start src/app.js --name nongfu-api --cwd /opt/nongfu/backend

pm2 status                 # status 应为 online
curl http://127.0.0.1:3000/health

# 4.2 保存进程列表 + 设置开机自启
pm2 save
pm2 startup                # 会打印一条 sudo 命令，复制那条命令单独执行一次
```

> 也可以用配置文件启动（已备好）：`pm2 start /opt/nongfu/deploy/ecosystem.config.js`，
> 好处是日志路径、内存上限、时区都写死了，更规范。

### 步骤 4：构建前端

```bash
cd /opt/nongfu/frontend

# 4.1 安装依赖（前端构建需要 devDependencies，所以不加 --omit=dev）
npm ci

# 4.2 构建 → 产出 frontend/dist/
npm run build
```

成功后会看到 `✓ built in xx s`，并生成 `dist/` 目录：

```bash
ls -lh /opt/nongfu/frontend/dist
# 应包含 index.html 和 assets/ 目录
```

> 💡 **前端构建吃内存**，2G 内存的机器可能 OOM。若报 `JavaScript heap out of memory`：
>
> ```bash
> NODE_OPTIONS=--max-old-space-size=1024 npm run build
> ```

### 步骤 5：配置 nginx

```bash
# 5.1 创建站点配置
vim /etc/nginx/sites-available/nongfu
```

把 `deploy/nginx-nongfu.conf` 的内容粘进去，只需改一处 `server_name`。

⚠️ 别漏掉这几个关键点（详见 1.5）：

- `try_files $uri $uri/ /index.html;` —— 前端是 **history 路由**，不加这行**刷新页面就会 404**
- `location /api/`、`location /product_images/`、`location /uploads/` —— **三条都要反代**
- `client_max_body_size 10m;` —— 上传 Excel / 商品图是 5MB 上限，nginx 默认 1MB 会直接 413
- `proxy_set_header X-Forwarded-Proto $scheme;` —— 后端用它拼图片地址，不加会让 HTTPS 页面里的图片 404/被浏览器拦截
- `/uploads/` 要透传 `Origin` 和 `Referer` —— 后端对这个目录有来源白名单守卫

```bash
# 5.2 启用站点
ln -s /etc/nginx/sites-available/nongfu /etc/nginx/sites-enabled/nongfu
rm -f /etc/nginx/sites-enabled/default    # 移除默认站点，避免抢占 80 端口

# 5.3 ⚠️ 先校验语法，再重载（语法错会直接让 nginx 起不来）
nginx -t
systemctl reload nginx
systemctl enable nginx
```

### 步骤 6：验证与访问

```bash
# 6.1 服务器本机自测（三层依次确认）
curl http://127.0.0.1:3000/health          # ① 后端活着
curl -I http://127.0.0.1/                  # ② nginx 能返回前端（期望 200）
curl -I http://127.0.0.1/product_images/SPBM001_image.png   # ③ 商品图可访问（期望 200）

# 6.2 检查前端 /api 反代是否通（期望 401，因为未登录 —— 关键是**不是 404**）
curl -i http://127.0.0.1/api/orders | head -3
```

**`/api/xxx` 返回 401 是正常的**（说明 nginx → 后端链路已通，只是没带登录令牌）；
如果返回 **404**，说明 nginx 反代没生效，回去检查 `location /api/`。

然后在浏览器打开 `http://<服务器公网IP>/`，用 `admin` / `admin123` 登录。

> ⚠️ **首次登录后立刻改掉 admin 默认密码**。

### 步骤 7：配置域名与 HTTPS（可选但强烈建议）

```bash
# 7.1 域名解析：在域名服务商处添加 A 记录 → 指向服务器公网 IP
#     （国内服务器需先完成 ICP 备案，否则 80/443 不通）

# 7.2 申请免费 HTTPS 证书（Let's Encrypt，自动续期）
apt install -y certbot python3-certbot-nginx
certbot --nginx -d <你的域名>
#    按提示输入邮箱、同意条款，它会自动改 nginx 配置并设置自动续期

# 7.3 验证自动续期
certbot renew --dry-run

# 7.4 若用域名，记得同步修改 backend/.env 的 CORS_ORIGIN，然后重启后端
pm2 restart nongfu-api
```

证书生效后，**立刻改 `backend/.env` 加上 `app.set('trust proxy', 1)` 相关说明见第 3.6 条**（后端需要信任代理头才能正确拼出 `https://` 图片地址）。

## 三、部署后如何确认「真的正常」+ 常见问题排查

### 3.1 新手最重要的方法：分层排查法

出问题时**不要乱猜**，按这四层从下往上查，在哪一层断了就修哪一层：

```
第 4 层  浏览器          ← F12 → Network 看真实请求和响应码；Console 看报错
第 3 层  nginx           ← curl -I http://127.0.0.1/         （本机测 nginx）
第 2 层  后端 Node       ← curl http://127.0.0.1:3000/health （本机测后端）
第 1 层  MySQL           ← systemctl status mysql
第 0 层  进程            ← pm2 status
```

**判读口诀**：

- 本机能 curl 通、外网访问不了 → **安全组 / 防火墙**问题
- 本机 3000 通、走 nginx 不通 → **nginx 配置**问题
- 3000 不通、pm2 显示 errored → **后端本身**问题（看 `pm2 logs`）
- `/health` 返回 503 → **数据库连接**问题（看 `.env`）

### 3.2 上线验收清单（逐条打勾）

```bash
# ① 进程与自启
pm2 status                                  # nongfu-api = online
pm2 save                                    # 已保存
systemctl is-enabled nginx mysql            # 均为 enabled

# ② 后端健康（关键指标）
curl -s http://127.0.0.1:3000/health | grep -o '"status":"[^"]*"'   # healthy

# ③ 数据库
mysql -u nongfu -p'<强密码>' nongfu_inventory -e \
  "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='nongfu_inventory';"   # 39

# ④ 前端产物存在
test -f /opt/nongfu/frontend/dist/index.html && echo "前端产物 OK"

# ⑤ 商品图片可访问（最容易漏的一项）
curl -sI http://127.0.0.1/product_images/SPBM001_image.png | head -1   # HTTP/1.1 200

# ⑥ 时区正确（错时区会让所有日期统计错一天）
date                                                                   # 显示 CST
```

**再进浏览器做一遍功能冒烟**：登录 → 打开「商品管理」（**看图片有没有裂图**）→ 新建一个订单 → 看仪表盘数据 → 导出一次 Excel。

### 3.3 常见问题速查表

| 现象                                | 最可能的原因                                                   | 排查命令 / 处理                                                                                                |
| ----------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 浏览器打不开，连接超时              | 安全组没放行 80/443；或 nginx 没启动                           | 腾讯云控制台查安全组；`systemctl status nginx`                                                                 |
| **502 Bad Gateway**                 | 后端没起来 / 端口不对                                          | `pm2 status`；`pm2 logs nongfu-api --lines 50`；`curl 127.0.0.1:3000/health`                                   |
| **504 Gateway Timeout**             | Excel 导入等慢请求，nginx 超时太短                             | 在 `location /api/` 里加大 `proxy_read_timeout 120s;`                                                          |
| 页面能打开，**一刷新就 404**        | nginx 少了 history 路由回退                                    | `location /` 里必须有 `try_files $uri $uri/ /index.html;`                                                      |
| **商品图片全部裂图**                | ① 漏传 `商品档案/商品图片/`；② nginx 没反代 `/product_images/` | `curl -I http://域名/product_images/SPBM001_image.png`；`ls /opt/nongfu/商品档案/商品图片 \| wc -l`（应 134）  |
| 接口全部 404，页面数据空白          | nginx 反代路径写错                                             | F12 看请求 URL；确认 `location /api/` + `proxy_pass http://127.0.0.1:3000;`（**结尾不加斜杠**）                |
| 登录后立刻跳回登录页                | `CORS_ORIGIN` 没加真实域名；或 JWT 密钥被改过导致旧 token 失效 | 改 `.env` 后 `pm2 restart nongfu-api`；浏览器 F12 看是否 401                                                   |
| 提示「数据库不可用」/ `/health` 503 | `.env` 里 DB 配置错 / MySQL 没起 / 密码不对                    | `systemctl status mysql`；`mysql -u nongfu -p nongfu_inventory -e "SELECT 1"`                                  |
| **上传 Excel 报 413**               | nginx `client_max_body_size` 太小（默认 1m）                   | 设为 `10m`（后端单文件上限是 5MB）                                                                             |
| 报 `EADDRINUSE`                     | 3000 端口已被占用                                              | `ss -lntp \| grep 3000` → `kill <PID>`，或改 `PORT`                                                            |
| 页面中文乱码                        | 库/表字符集不是 utf8mb4                                        | `mysql -e "SHOW VARIABLES LIKE 'character%'"`                                                                  |
| 上传的配送照片打不开（403）         | `/uploads/` 没透传 `Origin`/`Referer`                          | 在 nginx 该 location 里加 `proxy_set_header Origin $http_origin;` 和 `proxy_set_header Referer $http_referer;` |
| HTTPS 页面里图片不显示              | 后端拼出的图片地址是 `http://`（未信任代理头）                 | 在 `backend/src/app.js` 的 `const app = express();` 后加 `app.set('trust proxy', 1);`，然后重启                |
| 构建前端报内存不足                  | 机器内存太小                                                   | `NODE_OPTIONS=--max-old-space-size=1024 npm run build`                                                         |

### 3.4 记住这几个日志位置（排查必备）

```bash
pm2 logs nongfu-api --lines 100      # 后端日志（最常看）
pm2 logs nongfu-api --err            # 只看错误
tail -f /var/log/nginx/error.log     # nginx 错误日志
tail -f /var/log/nginx/access.log    # nginx 访问日志（看请求有没有进来）
```

> **看日志的正确姿势**：先看**最新一条**错误的**完整堆栈**，不要只看最后一行。
> 浏览器里的报错信息通常是「结果」，真正的「原因」在服务器日志里。

## 四、上线后：更新代码、重新发布、版本管理与回滚

### 4.1 铁律：任何变更前先备份

```bash
# 备份脚本已备好：deploy/backup.sh
bash /opt/nongfu/deploy/backup.sh
```

它做两件事：

1. `mysqldump` 导出当前数据库 → `/opt/backups/db-<时间戳>.sql`
2. 打包当前代码目录 → `/opt/backups/code-<时间戳>.tar.gz`

> ⚠️ **数据库备份和代码备份缺一不可**：代码可以 `git` 回滚，但**数据回不去**。

### 4.2 标准更新流程（每次改完代码都走这 6 步）

```bash
# ── 第 0 步：本机开发时先跑测试，确认没改坏 ──
cd backend && node scripts/run_smokes.js      # 后端冒烟
cd ../frontend && npm run ui-smoke            # 前端 UI 冒烟
git add -A && git commit -m "feat: 中文描述" && git push
git tag v1.2.0 && git push --tags             # 打版本标签（回滚靠它）

# ── 第 1 步：备份 ──
bash /opt/nongfu/deploy/backup.sh

# ── 第 2 步：拉新代码 ──
cd /opt/nongfu && git pull --ff-only

# ── 第 3 步：如果有数据库变更，先执行迁移（没有就跳过）──
#    ⚠️ 顺序：先迁移，再重启后端。迁移脚本是幂等的，可重复执行。
mysql -u nongfu -p'<强密码>' nongfu_inventory < database/migration_xxx.sql

# ── 第 4 步：更新依赖（package.json 有变化时才需要）──
cd backend && npm ci --omit=dev
cd ../frontend && npm ci

# ── 第 5 步：重新构建前端 ──
npm run build

# ── 第 6 步：重启后端 + 校验 ──
pm2 reload nongfu-api        # reload 比 restart 更平滑（先起新再停旧）
sleep 2
curl -s http://127.0.0.1:3000/health
curl -I http://127.0.0.1/     # 确认前端仍是 200
```

> 💡 上面这一整套可以用 `bash /opt/nongfu/deploy/deploy.sh v1.2.0` 一键完成（脚本已备好，含每步校验与失败即停）。

⚠️ **关键提醒**：

- **改了后端代码必须重启后端**，否则跑的还是旧代码（可用 `/health` 里的 `uptimeSec` 判断是否真的重启了）。
- **改了前端必须重新 `npm run build`**，否则 nginx 发的还是旧的 `dist`。
- **数据库迁移脚本一旦上线就不能删**，回滚时要靠它反向执行。

### 4.3 版本管理规范（简单但有效）

| 手段           | 做法                                                               | 作用                       |
| -------------- | ------------------------------------------------------------------ | -------------------------- |
| **Git 标签**   | 每次发布 `git tag v1.2.0`                                          | 回滚的坐标点，**必须做**   |
| **提交信息**   | `feat:/fix:/docs:` + 中文描述                                      | 出问题时能查到「哪次改的」 |
| **数据库迁移** | `database/migration_<日期>_<说明>.sql`，配套 `rollback_<说明>.sql` | 结构变更可逆               |
| **变更日志**   | 追加到 `docs/项目概览.md` 〇节                                     | 唯一事实源，团队对齐       |

> 本项目已有 `database/migration_*.sql` 与 `rollback_*.sql` 的配套惯例，**继续沿用**，不要另起一套命名。

### 4.4 回滚（三种情形，对号入座）

#### 情形 A：新版本代码有问题，数据库结构没变 —— 最常见

```bash
# 用脚本一键回滚到指定版本
bash /opt/nongfu/deploy/rollback.sh v1.1.0
```

脚本做的事：

```bash
cd /opt/nongfu
git fetch --tags
git checkout v1.1.0                    # 切回旧版本代码
cd backend && npm ci --omit=dev
cd ../frontend && npm ci && npm run build
pm2 restart nongfu-api
curl -s http://127.0.0.1:3000/health
```

#### 情形 B：数据库结构也变了，且有对应的 rollback 脚本

```bash
cd /opt/nongfu
git checkout v1.1.0
mysql -u nongfu -p'<强密码>' nongfu_inventory < database/rollback_xxx.sql   # ⚠️ 先执行数据库回滚
cd backend && npm ci --omit=dev
cd ../frontend && npm ci && npm run build
pm2 restart nongfu-api
```

⚠️ **顺序很重要**：**先回滚数据库结构，再回滚代码**。

#### 情形 C：数据被改坏了（最难）—— 只能用备份恢复

```bash
# ⚠️⚠️ 危险操作：会覆盖当前数据库全部数据！执行前先把现状也导一份
mysqldump -u nongfu -p'<强密码>' nongfu_inventory > /opt/backups/db-before-restore-$(date +%F_%H%M).sql

# 从备份恢复
mysql -u nongfu -p'<强密码>' nongfu_inventory < /opt/backups/db-2026-09-23_2200.sql
```

> ⚠️ 生产库的写操作**永远先备份**。本项目历史上曾因直接导入含 `DROP DATABASE` 的完整 dump 而误伤正式库，务必警惕。

### 4.5 自动化：每天自动备份

```bash
crontab -e
```

加入一行（每天凌晨 3:00 备份，保留最近 30 天）：

```cron
0 3 * * * /bin/bash /opt/nongfu/deploy/backup.sh >> /var/log/nongfu-backup.log 2>&1
```

再配合一条清理任务：

```cron
30 3 * * * find /opt/backups -name '*.sql' -mtime +30 -delete; find /opt/backups -name '*.tar.gz' -mtime +30 -delete
```

### 4.6 日常运维常用命令（贴在服务器上备用）

```bash
pm2 status                    # 看后端是否在线
pm2 logs nongfu-api           # 实时看日志（Ctrl+C 退出）
pm2 restart nongfu-api        # 重启后端
pm2 monit                     # 实时看 CPU / 内存

systemctl reload nginx        # 改完 nginx 配置后重载（先 nginx -t）
systemctl status nginx mysql  # 看服务状态

df -h                         # 看磁盘（日志和数据库备份容易占满）
free -h                       # 看内存
```

## 五、上线后必须做的安全收尾（新手最容易忽略）

1. ⚠️ **改掉 admin 默认密码**（`admin` / `admin123` 是本机开发账号）。
2. ⚠️ **确认 `backend/.env` 里 `MINI_DEV_LOGIN=0`** —— 置 1 会绕过微信身份校验，任何人都能按手机号登录。
3. ⚠️ **确认 3306 和 3000 没有对公网开放**（安全组 + 服务器防火墙双重确认）。
4. ⚠️ **两个 JWT 密钥必须不同且随机**，不要沿用本机那份。改动密钥会让所有人重新登录（这是正常的）。
5. ⚠️ **`.env` 权限收紧**：`chmod 600 /opt/nongfu/backend/.env`。
6. **建议用非 root 用户跑 Node**（进阶，但很重要）：`useradd -m app` → `chown -R app:app /opt/nongfu` → 用 `app` 用户执行 `pm2 start`。
7. **配置备份监控**：至少每天看一眼 `/health` 是否 200（可用腾讯云「云监控」的 URL 拨测）。
