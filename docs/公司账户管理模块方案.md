# 公司账户管理模块 — 实现方案（最终版）

> 版本：v2.0　日期：2026-09-02　状态：已实现
> 依据业务修正：新增三类账户为**相互独立、无特殊业务语义的普通账户**；菜单挂「基础信息管理」下；支持任意账户间互转。

---

## 一、账户体系（7 类，相互独立）

| account_type | 账户 | 属性 |
|:---:|------|------|
| 1 | 晟之溪公户 | 资金账户（原「其他支出」可选支付账户） |
| 2 | 水公社公户 | 资金账户 |
| 3 | 微信 | 资金账户 |
| 4 | 其他 | 资金账户 |
| 5 | **可上单信用余额** | 普通余额账户（无业务语义，仅名称区分） |
| 6 | **可上单折扣余额** | 普通余额账户（无业务语义，仅名称区分） |
| 7 | **自有费用余额** | 普通余额账户（无业务语义，仅名称区分） |

- 5/6/7 账户之间、以及与 1-4 资金账户之间**不存在默认逻辑或隐含关系**，均可独立作为转出方/转入方
- 账户状态：启用 / 停用（停用账户不可收付）
- 余额：`current_balance`（可用余额）；期初余额 `initial_balance` 仅创建时设置

## 二、数据模型

- `finance_accounts`：**结构不变**（account_type 语义扩到 7 类；通过迁移 seed 3 行：`ACCOUNT_CREDIT / ACCOUNT_DISCOUNT / ACCOUNT_FEE`，余额 0）
- `finance_transactions`：复用；账户间转账记**双流水**（转出 tx_type=2 支出 + 转入 tx_type=1 收入，同一 `tx_no` 与 `related_id`(XFER+批次)，`counterparty` 互指），便于对账
- 迁移：`database/migration_add_company_balance_accounts.sql`（幂等）；`full_schema_data.sql` 已重新导出

## 三、接口设计（`/api/finance-accounts`，独立 controller）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 账户列表（7 类：名称/类型/开户行/账号/可用余额/状态/备注） |
| POST | `/` | 新增账户（类型 1-7 下拉、名称唯一、期初余额≥0） |
| PUT | `/:id` | 账户设置（开户行/账号/备注/启用停用；名称与类型锁定） |
| DELETE | `/:id` | 删除（仅余额为 0 **且**无流水的账户，否则提示可停用） |
| POST | `/:id/adjust` | 人工调账 `{type: income\|expense, amount, remark}`（事务：余额±与流水） |
| POST | `/transfer` | **账户互转** `{fromId, toId, amount, remark}`（事务：双边余额+双流水） |
| GET | `/:id/transactions` | 账户流水（分页，可按日期/类型筛选） |

**校验与规则**
- 金额必须 > 0；转出账户与转入账户不能相同
- 转出可用余额不足 → 拦截「转出账户可用余额不足」
- 停用账户不可作为转出方或转入方
- 所有余额变更与流水写入均在同一数据库事务内，保证一致性

## 四、前端

- **菜单**：基础信息管理 → **公司账户管理**（二级菜单，`/accounts`）
- 页面 `views/account/CompanyAccounts.vue`：账户卡片（类型色标、余额、状态）+ 操作：
  - 「转账」：转出（默认当前账户，可改）/转入下拉（排除自身）、金额、备注
  - 「更多」：收入入账 / 支出登记 / 查看流水 / 账户设置 / 停用启用 / 删除
- 「新增账户」按钮；移动端卡片单列、弹窗 94vw

## 五、与其他模块的关系（低耦合）

- 「其他支出」模块仍只写 1-4 资金账户（`related_module='other_expense'`），与本模块共存互不干扰；本模块在「更多-查看流水」中可看到其影响
- 5/6/7 账户完全由本模块管理（人工收支 + 互转），无任何业务模块自动写入，便于后续独立扩展（如接入上单核销时仅需调用本模块记账入口）
