## 二、功能缺陷（优先级最高——不是"债"，是正在发生的错）

### F1. 出库失败提示"出库成功" 🔴 高
- **位置**：`frontend/src/views/inventory/InventoryList.vue:938`
- **问题**：`stockOut` 抛错进入 `catch` 后仍执行 `ElMessage.success('出库成功')` 并关闭对话框，用户完全不知出库失败。
- **影响**：库存台账与实际脱节，且用户以为操作完成。上一轮已修复入库/盘库的同类 bug，出库是漏网之鱼。
- **建议**：catch 中改为 `ElMessage.error(error.message || '出库失败')`，不关对话框。一行改动。

### F2. 请求失败回退 mock 假数据 🔴 高
- **位置**：`OrderList.vue:768-811`、`InventoryList.vue:697-725/751`、ProductList / SupplierList / WorkerList / StationList 共 6 处
- **问题**：各页面 `generateMockData()` 在接口失败时把伪造数据（含假订单、`total: 42`）塞进表格，用户会把测试假单当真实业务数据。
- **影响**：比报错更危险——静默展示错误数据，可能误导备货、对账决策。
- **建议**：删除全部 mock 函数与 catch 回退，失败显示空表 + 报错提示。

### F3. 取消订单永久损失已核销水票 🔴 高
- **位置**：`backend/src/controllers/orderController.js:576-605`（deleteOrder）、`655-684`（hardDeleteOrder）、`708-879`（updateOrder）
- **问题**：删除/更新订单时恢复了库存与水站欠款，但**未把已核销水票还原为 status=1**（可用）。
- **影响**：取消订单 = 客户水票永久作废，属资损级业务缺口。
- **建议**：在恢复库存的同一事务内 `UPDATE water_tickets SET status=1 WHERE related_order_id=?`（按实际表结构调整）。

### F4. 出库操作无台账记录 🔴 高
- **位置**：`backend/src/controllers/inventoryController.js:518-597`
- **问题**：`stockOut` 读取了 `out_type`、`remark` 但**从未落库**，事务里只有一条 UPDATE inventory——出库无任何台账可追溯。
- **影响**：出库无法对账、无法审计"谁在什么时候出了什么货"。
- **建议**：建 `stock_out_records` 表或在 `purchase_records` 对称位置记录，补台账 + 列表查询。

### F5. Excel 导入无事务，中途失败留半截数据 🔴 高
- **位置**：`backend/src/controllers/excelController.js:281-353, 362-378, 387-444`
- **问题**：三段导入逐行 execute + catch 吞错（console.error 后 failed++），无事务包裹。
- **影响**：导入 500 行在第 300 行失败，前 299 行已入库，用户不知情。
- **建议**：整体包事务，失败全部回滚并返回失败行明细；或明确声明"逐行提交"语义并给用户成功/失败汇总。

### F6. 商品下拉只取前 100 条 🟡 中
- **位置**：`OrderList.vue:815-818`
- **问题**：商品库存映射 `pageSize: 100`，商品超过 100 后下拉显示错误库存/误禁用。
- **建议**：改用专门的轻量接口（id/name/stock 全量）或搜索式远程加载。

## 三、安全隐患

### S1. 9 组核心路由完全无鉴权 🔴 高
- **位置**：`backend/src/routes/` 下 costRoutes、dashboardRoutes、excelRoutes、machineStationRoutes、**orderRoutes**、productRoutes、stationRoutes、supplierRoutes、workerRoutes（已验证：grep "auth" 计数为 0）
- **影响**：下单、删单、Excel 导入导出、商品/员工/供应商增删改全部**匿名可调用**。已挂 auth 的 9 个路由（expense/financeAccount/financial/inventory/salary/salesman/statistics/waterTicket/auth）说明团队知道规范，只是没铺完。
- **建议**：统一在 `app.js` 挂全局 `app.use('/api', auth)` 后对 authRoutes 放行，一处改动覆盖全部，杜绝以后新路由忘挂。

### S2. JWT 密钥硬编码 + 公开在 .env.example 🔴 高
- **位置**：`backend/src/middleware/auth.js:3`（`|| 'nongfu_inventory_secret_2026'`）、`backend/.env.example:22`（同一真实值进 git）
- **影响**：拿到源码即可伪造任意用户 token（含 admin）。
- **建议**：删除 fallback，启动时校验 `process.env.JWT_SECRET` 缺失即拒绝启动；.env.example 改为占位符；轮换现有密钥（会让旧 token 全部失效，择机做）。

### S3. CORS 全开 + 无安全头 + 无限流 🔴 高
- **位置**：`backend/src/app.js:30`（`app.use(cors())` = origin `*`）
- **影响**：任意第三方网页可跨域调用 API（配合 S1 等于完全裸奔）；无 helmet、无 express-rate-limit。
- **建议**：CORS 白名单（开发环境 localhost:5173，生产域名）；引入 helmet；登录接口加 rate-limit（如 15 分钟 10 次）。

### S4. 无角色鉴权，任何登录用户可调管理接口 🔴 高
- **位置**：后端全目录——JWT 已带 role，但无任何 `role === 'admin'` 判断
- **影响**：普通员工 token 可删除账户、调整余额、作废入库单（横向越权）。
- **建议**：在 auth 中间件上扩展 `requireRole('admin')`，管理类接口（账户调账/转账/作废/用户管理）挂上。

### S5. Excel 上传无限制 + xlsx 库已知漏洞 🔴 高
- **位置**：`backend/src/controllers/excelController.js:7`（memoryStorage，无 limits/fileFilter）；`backend/package.json` xlsx 0.18.5（CVE-2023-30533 原型污染/ReDoS，npm 版已停更）
- **影响**：匿名（S1）+ 无大小限制 = 用大文件打爆内存；xlsx 解析存在配方炸弹风险。对比 `expenseIoController.js:8` 已有 5MB 限制，说明规范存在但没复用。
- **建议**：multer 加 `limits: { fileSize: 5MB }` + fileFilter（.xlsx/.csv）；解析前校验行数上限；xlsx 换 SheetJS 官方 CDN 源或 exceljs。

### S6. admin 弱口令 + 测试数据含 PII 🟡 中
- **位置**：`backend/src/scripts/seed_user.js:20`（admin123）；`database/test_data.sql`（客户手机号/银行账号/地址混入 `full_schema_data.sql` 全量包）
- **建议**：生产部署强制改密；全量包拆分出"结构+种子数据"与"演示数据"两层。

### S7. 错误信息泄露内部细节 🟡 中
- **位置**：`backend/src/app.js:89`、`orderController.js:121`、`inventoryController.js:352`、`excelController.js:245` 等把 `err.message` 直出客户端
- **建议**：生产环境统一返回固定文案，`err.message` 只进日志。

### S8. 登录无防暴力破解；token 存 localStorage 🟡 中
- **位置**：`authController.js:9-56`（无失败锁定）；`Login.vue:101`（localStorage，XSS 可窃取）
- **建议**：限流（同 S3）；前端可后续评估 httpOnly cookie 方案，短期先保证 XSS 面收敛。

### S9. 前端路由守卫只查 token 存在性 🟡 中
- **位置**：`frontend/src/router/index.js:171-178`
- **建议**：守卫中校验 token 过期时间（本地解码 exp），过期即踢回登录。

### S10. baseURL 写死 localhost 🔴 高（部署阻断级）
- **位置**：`frontend/src/api/request.js:6`（`baseURL: 'http://localhost:3000/api'`）
- **影响**：一旦部署到服务器，前端全部请求 404。
- **建议**：改 `import.meta.env.VITE_API_BASE`，.env.development/.env.production 各配一份。

## 五、架构设计问题

- **位置**：`orderController.js:740-745` —— `beginTransaction()` **之前**调用了 `connection.rollback()`
- **影响**：当前恰好无害，但校验路径一变即成连接泄漏/回滚失效隐患。

## 七、测试覆盖

### T1. 后端零自动化测试，仅 3 个冒烟脚本 🔴 高
- **现状**：无 test 目录、无测试框架依赖；只有 smoke_stockin_account.js（41 断言）、expense/account 冒烟等 3 个手工脚本，覆盖最近 3 个模块，**核心的订单创建/更新/删除、水票核销、财务统计完全没有回归手段**。
