## 一、项目背景与目标

**农夫山泉经销商进销存管理系统**：为一个农夫山泉经销商（水/饮料批发零售）定制的单体仓库管理系统，覆盖商品/库存/供应商/员工等基础档案、进销存订单、营收统计、成本统计、工资发放、公司账户资金记账。

- **使用者**：经销商内部人员（管理后台 Web 单端；原微信小程序已于 2026-08-23 彻底删除）。
- **演进特点**：业务规则随经销商实际经营多次调整（订单类型 5 返货模式改为水票机制、营收口径重构、业务员并入员工管理等），**以 `docs/项目概览.md` 为唯一事实源**，README.md 偏早期已过时（写 5 个模块，实际 30 张表），仅供参考勿采信。
- **需求文档**：`docs/需求细分-订单类型调整与水票系统.md`、`docs/成本统计模块需求确认.md`、`docs/公司账户管理模块方案.md`。

## 三、关键技术决策及原因

| 决策 | 原因/背景 |
| :--- | :--- |
| 请求体统一 camelCase + `middleware/normalizeBody.js` 全局蛇→驼 | 前端全发驼峰；controller 内**禁止** `body.xxx_yyy \|\| body.xxxYyy` 双命名判定（曾致字段不对称 bug：`deliveryMethod` 非 `deliveryType`）。multer multipart 不经此中间件 |
| 订单定价/库存/欠款/水票核销集中在 `services/orderPricingService.js` | 此前在 orderController 重复实现（930 行）；服务化后 createOrder/updateOrder/取消/删除共用一份逻辑 |
| 营收口径唯一归后端 `utils/revenueExpr.js`（`itemRevenueExpr` SQL 表达式） | 前端 JS 曾抄一份口径导致报表漂移（A6）；订单类型 1/2/3 计营收，4/6 机台走 machine_sales |
| xlsx → **exceljs** 换库（`utils/excel.js` shim 统一读写/CSV） | xlsx 库停更且有漏洞；exceljs 不支持旧版 .xls，上传白名单已移除；列宽一律 `ws.getColumn(n).width`（`ws.columns` 可能为 null） |
| 资金记账三联事务（业务记录 + 余额 + 流水） | 见第八节规范第一条，保证「余额 = initial_balance + 流水净额」恒成立 |
| 菜单单一数据源 `layout/menuConfig.js` | 菜单与 router meta 曾双份维护漂移；A8 改造后 router `meta.title` 从 `MENU_TITLES` 导入 |
| 业务员并入员工管理（2026-09-04） | `salesmen` 模块删除，数据迁入 `workers.employee_type=3`（worker_id 沿用 SM 编号保历史引用）；`salesmen` 表只读归档保留 |
| echarts 按需引入（`@/utils/echarts`） | 全量引入 chunk 超限；仅注册 Line/Pie/Bar + Grid/Tooltip/Legend |
| 巨页不拆（OrderList 1470 行 / InventoryList 1310 行） | 高频迭代页拆分回归风险 > 可读性收益，留待功能迭代时顺势抽组件 |

## 六、代码风格与开发规范

**必须遵守**（完整原文在 `.workbuddy/memory/MEMORY.md`，此处为摘要）：

1. **资金记账统一规范**：任何账户余额变动必须同一事务完成「业务记录 + `finance_accounts.current_balance` + `finance_transactions` 流水」；先 `FOR UPDATE` 行锁校验余额；流水分录字段齐全（tx_type/tx_category/balance_before/balance_after/related_module/related_id…）；撤销操作回补余额+处理流水；事务内业务校验失败抛 `e.business=true` 由 catch 统一 rollback 后返 400——**严禁** `beginTransaction()` 后直接 `return error(...)`。
2. **接口规范**：写操作挂 `auth` JWT；操作人取 `(req.user && (req.user.username || req.user.id)) || null`；分页 `parseInt` 后内联；金额 `Math.round(n*100)/100`。
3. **数据库变更流程**：写幂等 `migration_*.sql`（information_schema 判存）→ **node + mysql2 执行**（勿用 mysql.exe，Windows 中文乱码）→ `node backend/scripts/export_dump.js` 重导 full_schema_data.sql → 导出前确认无测试残留。
4. **前端约定**：窄屏适配（对话框 ≤768px 退化 94vw、长表单 body 限高滚动）；任何页面/表单/交互调整同步更新 `docs/项目概览.md`；提交失败分支不得误报成功（发现即修）；菜单改动只改 `menuConfig.js`。
5. **新代码驼峰单读**：controller 读 `req.body` 一律驼峰（D7 归一化保证），不写蛇形别名回退。
   ⚠️ **命名陷阱**：归一化是按规则的机械转换（`delivery_type`→`deliveryType`），若某字段前端用的是**另一个**驼峰名，两者不会自动对齐。订单接口有三个这样的字段——配送方式（归一化 `deliveryType` / 前端 `deliveryMethod`）、配送员工（`workerId` / `deliveryStaffId`）、创建人（`createdBy` / `createdById`）。`normalizeOrderPayload` 已同时兼容两套名，**新增字段前先确认前端实际传的是哪个名字**（2026-09-10 曾因二者不一致导致蛇形调用全部取空）。

## 八、环境配置与运行方式

**环境要求**：Windows（bat 脚本）、Node.js（后端用本机 node，22+ 均可）、MySQL 8.x（3306 端口运行中）。

**首次部署 / 新机器**：
1. 改 `start.bat` 顶部 `DB_PASSWORD`（MySQL root 密码；`NPM_REGISTRY` 默认 npmmirror）。
2. 双击 `start.bat`：自动检测 MySQL → `init_db.js` 幂等初始化（执行 full_schema_data.sql）→ 缺依赖时 npm install → 后台拉起前后端（日志 `backend.log`/`frontend.log`，PID 存 `*.pid`）→ 等 6 秒自动打开 `http://localhost:5173`。
3. 默认账号见种子数据（`seed_user` / admin，详见 full_schema_data.sql 的 users 表 INSERT）。

**日常命令**：
- 启动 `start.bat`（前后端一起，detached）｜停止 `stop.bat`。
- 前端构建：`cd frontend && node node_modules/vite/bin/vite.js build`（若 dist 清空被守卫拦截：先 `mv dist dist_bak`）。
- 冒烟回归（改对应逻辑前必跑）：`cd backend && node scripts/smoke_order_pricing.js`（其余见第四节表格）。

**改后端代码后必须重启服务再验证**：`stop.bat` → `start.bat`（或手动杀 3000/5173 端口进程重启）。
